# Деплой на Vercel

Код уже запушен в `zarabotaet/wtt` (ветка `main`). Дальше — только шаги в
аккаунте Vercel, их нужно сделать руками (агент не может создавать проект
от твоего имени).

## 1. Импортировать проект

1. Зайди на https://vercel.com/new
2. **Import Git Repository** → выбери `zarabotaet/wtt` (если репозиторий
   не виден — сначала подключи GitHub-аккаунт/организацию `zarabotaet`
   через **Add GitHub Account** в том же экране).
3. Vercel сам определит фреймворк как **Next.js** — настройки сборки
   трогать не нужно (`npm run build`, output — автоматически).
4. **Root Directory**: оставь `.` (корень репо) — весь Next.js-проект
   лежит в корне, не в подпапке.
5. Жми **Deploy**.

Первый деплой займёт минуту-две. После него получишь домен вида
`wtt-<hash>.vercel.app` — это и есть рабочий сайт.

## 2. Переменные окружения (опционально, но желательно)

В **Project Settings → Environment Variables** добавь:

| Имя | Значение | Зачем |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | `https://<твой-домен>.vercel.app` (или кастомный домен, если подключишь) | Используется в `app/sitemap.ts` для абсолютных URL в sitemap.xml — без неё используется заглушка `https://wtt-matches.vercel.app`, что даст неправильные ссылки в сайтмапе |

После добавления переменной — **Redeploy** (Vercel не подхватывает новые
env-переменные для уже собранного деплоя автоматически).

## 3. Проверка после деплоя

- Открой `https://<домен>/` — должен редиректнуть на ближайший
  активный/будущий турнир.
- Открой `https://<домен>/events` — список турниров с поиском.
- `curl -s https://<домен>/events/<eventId> | grep -o '<title>[^<]*</title>'`
  — должен показать реальное название турнира (не заглушку) — подтверждает,
  что SSR реально рендерит контент.
- `https://<домен>/sitemap.xml` и `https://<домен>/robots.txt` — должны
  открываться.

## 4. Аналитика (Vercel Analytics)

`@vercel/analytics` уже подключён в коде (`app/layout.tsx`). Чтобы данные
начали собираться:

1. В дашборде проекта — вкладка **Analytics** → **Enable**.
2. Через несколько минут после первых визитов на сайт там появятся
   графики page views.

Дополнительных action'ов в коде не требуется — компонент `<Analytics />`
уже везде, где нужно.

## 5. Автодеплой на будущее

Vercel сам подписывается на пуши в `main` при импорте через GitHub —
никаких дополнительных webhook'ов настраивать не нужно. Каждый `git push`
в `main` будет триггерить новый деплой автоматически, а пуши в другие
ветки/PR получат Preview-деплои с отдельными URL.

## 6. Кастомный домен (когда будет нужен)

**Project Settings → Domains** → добавь домен, следуй DNS-инструкциям,
которые покажет Vercel (обычно один `CNAME`-рекорд). Ничего в коде менять
не нужно — только не забыть обновить `NEXT_PUBLIC_SITE_URL` на новый домен
и передеплоить (см. пункт 2).
