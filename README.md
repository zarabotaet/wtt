# WTT Matches Viewer

Неофициальный просмотрщик матчей World Table Tennis (WTT) — карточки
предстоящих/live/завершённых матчей с реальным счётом, живым обновлением,
фильтрами и кэшированием на клиенте.

**Статус:** рабочий прототип (один HTML-файл), готовится миграция на
Next.js для SSR/SSG (SEO) + деплой на постоянный домен + аналитика.

## Что уже есть

`prototype/wtt-matches.html` — полностью рабочая одностраничная версия:

- Список турниров с поиском, статусом (идёт/будущий/прошедший), сортировкой
- Карточки матчей: игроки, счёт по геймам, стол, раунд, статус
- Три секции — Предстоящие / Текущие / Прошедшие (не рендерятся, если пустые)
- Фильтры: тип события, стол, дата
- Тёмная/светлая тема (с учётом системной)
- Кэш в IndexedDB (никогда не перезапрашивает уже известный счёт
  завершённого матча повторно)
- Автообновление раз в 30 сек, пока есть live-матчи
- Ползунок масштаба карточек

Работает **только если открыт как обычный файл в браузере** (не через
встроенный превью каких-либо AI-чатов — там режется сеть до внешних API).

## Почему нужен переезд на Next.js

Текущая версия — чистый клиентский `fetch()` в браузере пользователя.
Из-за этого:

1. **SEO = ноль.** Поисковики не видят карточки матчей — весь контент
   рисуется JS-ом после загрузки пустого HTML.
2. **Все API-костыли видны в devtools** — не критично, но не любой домен
   отдаёт данные без Origin/Referer-проверки (см. `docs/API_REFERENCE.md`
   — там же список, какие домены открыты, какие нет).
3. Нет единого места для аналитики/деплоя/домена.

Next.js (или Remix/Astro/SvelteKit — см. `docs/ARCHITECTURE_PLAN.md` для
сравнения) решает всё разом: **серверный fetch не подчиняется CORS**, так
что все обходные пути с "открытым доменом" вообще перестают быть нужны —
сервер стучится в WTT API напрямую, без ограничений браузера.

## Как начать работу с этим в Claude Code

1. Распакуй архив, открой папку в Claude Code.
2. Дай ему прочитать `CLAUDE.md` — там всё необходимое для старта.
3. `docs/API_REFERENCE.md` — обязательно прочитать перед любыми правками
   логики загрузки данных. Там задокументирован **критический баг**,
   который отъел половину этой сессии разработки (структура
   `Competition.Unit[]` — это МАССИВ матчей, а не один матч).

## Важная оговорка

Это неофициальный клиент к недокументированному API worldtabletennis.com.
Эндпоинты найдены реверс-инжинирингом фронтенда сайта, могут измениться
или пропасть без предупреждения в любой момент. Не является продуктом
WTT/ITTF. При продакшн-использовании стоит:
- не долбить их API чаще, чем нужно (кэш уже заложен в архитектуру);
- быть готовым, что путь эндпоинта или структура ответа поменяются;
- рассмотреть добавление своего сервер-сайд кэша (Redis/KV) перед прод-запуском,
  чтобы не зависеть от доступности стороннего API при каждом заходе пользователя.
