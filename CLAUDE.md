# Инструкции для агента (Claude Code)

Это продолжение проекта, начатого в чате с Claude (не в Claude Code) —
там был реверс-инжиниринг недокументированного API WTT и рабочий
одностраничный HTML-прототип. Твоя задача — превратить это в нормальный
Next.js-проект с SSR/SSG, задеплоить на рабочий домен, подключить
аналитику.

## Порядок чтения (важно, в этом порядке)

1. `README.md` — общая картина, зачем всё это.
2. `docs/API_REFERENCE.md` — **обязательно перед тем как трогать
   логику загрузки данных**. Там задокументирован критический баг
   (`Competition.Unit[0]` vs полный массив `Unit[]`), который стоил
   половины сессии разработки. Если начнёшь переписывать парсинг с
   нуля, не читая это — велика вероятность наступить на те же грабли.
3. `prototype/wtt-matches.html` — рабочий референс. Открой в браузере,
   посмотри, как это выглядит и ведёт себя, прежде чем проектировать
   компоненты. Весь JS в файле (один `<script>` в конце) — это уже
   рабочая, проверенная на живых данных реализация всей логики: дедуп,
   слияние источников, паддинг кодов матчей, кэш в IndexedDB, фильтры.
4. `docs/ARCHITECTURE_PLAN.md` — куда и как переносить код из прототипа.
5. `docs/KNOWN_ISSUES.md` — что доделать, что осознанно отложено.
6. `docs/SEO_AND_ANALYTICS.md` — когда дойдёшь до SEO/деплоя/аналитики.

## Ключевое правило

**Не переписывай логику работы с API с нуля.** Она уже отлажена на живых
данных за много итераций (см. историю багов в `KNOWN_ISSUES.md` —
почти все они были найдены и исправлены через долгий цикл проверки на
реальном сайте worldtabletennis.com). Переноси функции из
`prototype/wtt-matches.html` почти дословно, меняя только место
исполнения (браузер → сервер).

Если найдёшь в API WTT что-то, что противоречит `API_REFERENCE.md` —
скорее всего, это WTT что-то поменяли на своей стороне (у них
недокументированный API, ломается без предупреждения), а не ошибка в
документе. Перепроверь вживую перед тем как чинить код под новое
поведение.

## Технологический стек (предлагаемый, не жёстко обязательный)

- Next.js 14+, App Router, TypeScript
- Хостинг: Vercel (проще всего для ISR + свой домен + Vercel Analytics)
- Без выбора конкретной CSS-системы — в прототипе уже есть свой
  дизайн-язык на CSS-переменных (тёмная/светлая тема), можно перенести
  как есть в `globals.css`, не обязательно тащить Tailwind/др.

## Что спросить у пользователя, если неясно

- Какой домен уже куплен/выбран для деплоя (или помочь выбрать/купить).
- Нужна ли поддержка нескольких языков (сейчас всё на русском).
- Приоритет: сначала красиво и по SEO, или сначала фичи (больше турниров/
  статистики/истории встреч между игроками)?
- Какую аналитику предпочитает (см. таблицу в `SEO_AND_ANALYTICS.md`) —
  зависит от того, где будет хостинг.
